# Architecture

Status: speech foundation exists (see `speech.md`); everything else is
planned. Update this file as each part is built, and mark what is planned
and what exists.

## Layers

1. **Upstream game** (everything not listed below). Kept as close to upstream
   as possible. Changes are limited to hooks in the hook list.
2. **Accessibility layer**, planned under `src/access/`. All speech, sound
   cues, navigation, commands and settings. Speech goes through Prism, loaded
   in-process with LuaJIT FFI. No other speech system, no fallback, no bridge.
3. **Launcher**, planned under `launcher/`. A separate native Windows app (C#
   Windows Forms on .NET 10, agent recommendation) with standard controls.
   It starts the game program with command-line arguments.

## Observation principles

From the old project's seam research, to be re-checked against v0.3.98
before relying on it:

- Read settled game state once per update, after the state stack updates.
  Do not scrape what is drawn, and do not speak from the render loop.
- Prefer read-only observation of game data (map, collision, warps, NPCs,
  party, battle state) over hooks. Most navigation needs no hooks.
- Upstream's mod *events* can be observed without changing behaviour. Its
  mod *hooks* are middleware and can change behaviour, so do not use them
  merely to observe.
- Battles need their own adapter, because battle text does not go through
  the normal text box.

## Launcher to game interface

Upstream's `main.lua` (v0.3.98, `love.load`) already supports everything the
launcher needs, so no game-side change is planned. Our launcher
(`launcher.md`) uses the first two rows and the updater switch.

| Purpose | How | Status |
|---|---|---|
| Start a specific game, skipping upstream's launcher | `POKEPORT_GAME=red`, `blue`, `yellow`, `gold`, `silver` or `crystal`; optional `--slot <id>` | exists upstream; verified 2026-10-31, through our launcher 2026-11-01 |
| Import a ROM without any launcher | `POKEPORT_IMPORT_ROM=<path>` with `POKEPORT_IMPORT_ONLY=1`; quits when done | exists upstream |
| Open upstream's own save editor | `--editor`, optional `--save <path>`, game from `POKEPORT_VERSION` | exists upstream; not used by our launcher, which has its own window (decision 39) |
| Keep upstream's self-updater off | `POKEPORT_PORTMASTER_MANAGED=1` (checked only by the updater and `Prelaunch`) | exists upstream; our launcher sets it (`launcher.md`) |

**Do not pass `--game` on the command line from source** (`love . --game red`): on 2026-10-31 that failed before `main.lua` ran (no output at all, with the layer on or off), and the owner saw LÖVE's blue error screen. `POKEPORT_GAME=red` works. Re-check this for packaged builds.

Without a game choice, upstream's own proprietary launcher opens from a source
checkout. A packaged build has no such path: it exits with code 40 (`launcher.md`, "Packaged release").

## Packaging notes (for the launcher workstream)

- **Upstream's self-updater is off in our builds.** `src/update/Boot.lua`
  and `Check.lua` download upstream's `gen1recomp-X.Y.Z.love` and mount it above the
  bundled code, which would replace our layer with plain upstream. Our package runs unfused and
  unstamped, the launcher sets `POKEPORT_PORTMASTER_MANAGED=1`, and `PackagedBuild` turns it off.
- Upstream's proprietary launcher files (License Term 2) are not in our package;
  `launcher/package_release.py` audits that.
- Upstream connects to Discord rich presence at start-up when Discord is
  running (log: "discord: rich presence connected"). Decide whether our build
  keeps that; it shares what the player is doing with Discord.

## Could this be a mod? (test, 2026-11-04)

A throwaway mod (not in the repository) with the `engine_internals` permission ran on this repository's game with `POKEPORT_ACCESS=0`, in Red, Crystal and FireRed, by script. It was not run on an official upstream build.

| Need | Result |
|---|---|
| Speech (Prism through FFI) | **Refused.** `require("ffi")` fails and the global is absent in all three. |
| Reading engine modules | Allowed for the running generation's modules; other generations' are refused. |
| Reading dialogue | Worked: Red's text boxes, including Oak's speech, from a mod; FireRed's messages. Crystal's text was not read, because the probe did not look in its Typer. Not a refusal. |
